# Tasks: catálogo de programas y anexo exigido por programa

**Input**: documentos de diseño en `specs/009-program-catalog-annex/`

**Prerequisites**: `plan.md`, `spec.md`, `research.md` (D1–D11), `data-model.md`, `contracts/openapi.yaml`, `quickstart.md`

**Tests**: **obligatorios**. El proyecto tiene TDD estricto: el rojo se observa antes de implementar. Cada tarea marcada `(RED)` debe fallar **por la razón esperada**, que la tarea nombra, antes de escribir la que la pone en verde, y cada tarea `(MUTANTE)` comprueba que la aserción afirma lo que su nombre dice. Las tareas `(GUARDA)` **no** son RED: están verdes antes de escribirlas y fijan algo que ya se cumple para que la implementación no lo rompa; etiquetarlas RED diluiría la regla. Las tareas `(FIXTURE)` corrigen datos de prueba que la implementación rompería **por diseño**, y se hacen antes para que el único rojo sea el esperado.

## Formato: `[ID] [P?] [Story] Descripción`

- **[P]**: puede ejecutarse en paralelo (archivos distintos, sin dependencias pendientes)
- **[Story]**: a qué historia pertenece (US1, US2)
- Toda tarea lleva la ruta exacta del archivo

## Convención de verificación

```bash
docker start tramita-postgres && ./mvnw clean verify
```

⚠️ **`clean` no es opcional al medir en rojo.** La compilación incremental de Maven puede dar un rojo falso o esconder uno verdadero.

⚠️ **Nunca `-q` junto a `-Dtest=`**: no imprime la línea «Tests run», y entonces un exit 0 **no prueba que los tests corrieran**. El separador de `-Dtest=` es la **coma**, no el `+`.

**Un IT suelto** (medido en la 008 sobre este pom): `./mvnw clean verify -Dtest=NONE -Dsurefire.failIfNoSpecifiedTests=false -Dit.test=<Clase>`. `-Dsurefire.skip=true` **no** salta los unitarios.

⚠️ **Los RED de IT se observan ANTES de escribir los RED unitarios.** En esta feature los RED unitarios (T016–T018, T033) fallan **por compilación**: nombran una excepción o un constructor que todavía no existen, y un error de compilación en `src/test` impide correr **todos** los tests, IT incluidos. Si se escriben primero, los RED de IT quedan tapados.

⚠️ **Los mutantes se revierten con `cp` desde una copia**, nunca con `git checkout` mientras haya trabajo sin commitear. Tras restaurar, `diff -q` contra la copia.

**Línea base al empezar**: el último conteo registrado es **163 unitarios + 127 IT** en `ca5decf` (`CLAUDE.md`, bloque de la 008). Se re-mide en T001; no se cita de memoria.

**Dos migraciones, y solo dos**: `V5.0.0` y `V5.1.0` (research D7). Ninguna tarea toca una tabla existente; si alguna parece necesitarlo, se salió del diseño (research D3, `data-model.md`).

**Cada fase cierra con un commit de unidad de trabajo**: Conventional Commits en español con la plantilla `.gitmessage` (activarla con `git config commit.template .gitmessage` si no está), cuerpo con el **porqué** y línea `Verificado:` con el comando y su resultado. Sin atribución de IA.
